# BG-002 关键词筛选与空状态

本目标在离线列表上增加即时名称筛选。输入名称片段即可筛选，首尾空白不参与匹配，英文忽略大小写；清空后恢复全部 3 条示例。

## 阅读顺序

1. [SubjectListState.kt](../composeApp/src/commonMain/kotlin/dev/bangumi/demo/ui/state/SubjectListState.kt)：保存输入、处理更新和清空事件、按名称筛选。
2. [App.kt](../composeApp/src/commonMain/kotlin/dev/bangumi/demo/ui/App.kt)：保存状态对象，把值与事件回调传给页面。
3. [SubjectListScreen.kt](../composeApp/src/commonMain/kotlin/dev/bangumi/demo/ui/screens/SubjectListScreen.kt)：展示搜索框、结果数量、列表或空状态。
4. [SubjectListStateTest.kt](../composeApp/src/commonTest/kotlin/dev/bangumi/demo/ui/state/SubjectListStateTest.kt)：验证筛选边界与连续操作。

## 用 Java 理解状态更新

一次输入的路径是：文本框产生新字符串 → `updateQuery` 保存原文 → Compose 观察到状态变化 → 读取 `visibleSubjects` → 页面显示新结果。

| Kotlin 写法 | 用途与 Java 对照 |
| --- | --- |
| `var query by mutableStateOf("")` | `var` 允许修改；`by` 把读写委托给状态对象。可以类比带变化通知的 getter/setter，普通 Java 字段赋值本身不会自动更新界面。 |
| `private set` | 外部只能读，修改必须经过事件方法，类似只公开 getter。 |
| `val visibleSubjects ... get()` | 自定义 getter，每次读取计算结果；类似 Java 的 `getVisibleSubjects()`，不是另存一份可变列表。 |
| `remember(subjects)` | 重组（Compose 因状态变化重新执行界面代码）时复用状态对象。`subjects` 按相等性比较发生变化时重新创建；关闭应用后不保存。 |
| `(String) -> Unit` | 接收字符串、不返回有用值的函数类型，类似 `Consumer<String>`；`Unit` 在这里可类比 `void`。 |
| `() -> Unit` | 不接收参数的回调，类似 `Runnable`。 |
| `state::updateQuery` | 函数引用，类似 Java 的同名方法引用，传递操作而不是立即执行。 |
| `subjects.filter { subject -> ... }` | 类似 `stream().filter(...).toList()`，按原顺序保留匹配条目，不改变原列表。 |

输入框保留原文，只对匹配用的局部变量调用 `trim()`，避免每次输入空格都被强制删掉。筛选总是基于完整列表，所以先输入“书店”再换成“星海”，依然能找到星海邮递员。

页面接收结果和回调，不直接筛选或获取数据。空列表时展示提示和清空按钮；两个清空按钮最终调用同一个 `clearQuery()`。

## 验证方式

构建是把源码编译并组装为可运行产物；依赖是代码使用的外部库。此次增加的 `kotlin("test")` 使用项目 Kotlin 插件对应版本，提供测试注解和断言。

在项目根目录使用下面的 PowerShell 命令：

```powershell
.\gradlew.bat :composeApp:assemble :composeApp:check --console=plain --no-daemon
.\gradlew.bat :composeApp:run
```

`commonTest` 中的 9 个测试由当前桌面目标执行，覆盖空白、名称片段、顺序、英文大小写、仅搜索名称、无匹配、空数据源、连续输入及清空恢复。测试报告在 `composeApp/build/reports/tests/desktopTest/index.html`。

窗口验收：初始 3 条 → 输入“书店”显示 1 条 → 清空恢复 3 条 → 输入不存在的名称显示空状态 → 点击“清空关键词”恢复 3 条。用 Tab 切换焦点也应能操作清空按钮。

测试验证逻辑，窗口操作验证事件连接与显示，两者不能互相替代。实际结果统一见 [进度记录](PROGRESS.md)。
